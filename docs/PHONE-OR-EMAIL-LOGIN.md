# ورود و ثبت‌نام با موبایل یا ایمیل

درخواست مشتری ۲۰۲۶-۱۰-۰۴: یک شناسه کافی است؛ موبایل یا ایمیل. تصمیم جدید مالک در همان روز، مسیر قبلی «فقط رمز» را تکمیل/جایگزین می‌کند: ورود موبایلی باید OTP پیامکی داشته باشد و ایمیل به‌عنوان مسیر جایگزین باقی بماند. تا وقتی سرویس پیامک واقعی و کلیدهای آن تنظیم نشده‌اند، نباید ورود پیامکی در رابط به‌صورت فعال نمایش داده شود یا OTP در لاگ نوشته شود.

## انتخاب پکیج OTP

| رتبه | روش/پکیج | امتیاز | دلیل |
|---:|---|---:|---|
| ۱ | `fouladgar/laravel-otp ^6.2` | ۱۰ | Laravel 13/PHP 8.3، purpose مستقل، rate-limit، انقضا، تست‌پذیری و کانال ارسال قابل تعویض |
| ۲ | Spatie One-Time Passwords | ۸ | معتبر و پخته، اما نسخه فعلی PHP 8.4 می‌خواهد و با مبنای PHP 8.3 پروژه هم‌خوان نیست |
| ۳ | OTP داخلی مینیمال | ۷ | کنترل کامل ولی نگهداری امنیتی بیشتر |
| ۴ | پکیج‌های Laravel 13 بسیار تازه | ۵ | سازگار ولی سابقه نصب/استفاده کم |
| ۵ | OTP وابسته مستقیم به یک فروشنده SMS | ۳ | قفل‌شدن معماری به یک سرویس‌دهنده و مهاجرت سخت‌تر |

منتخب: `fouladgar/laravel-otp`. پکیج و lock معتبر روی شاخه کاری نصب و با PHP 8.3، Composer validate، migrate:fresh، کل تست‌های بک‌اند و Composer audit آزموده شده است. فعال‌سازی ارسال واقعی منتظر خرید سرویس پیامک و تنظیم API key/pattern است.

## مانع مشخص و نقشه اجرا

`users.email` اکنون اجباری است. اختیاری‌کردن ایمیل برای مشتری و افزودن شماره هویتی یکتا، تغییر محدود و آزموده ساختار داده می‌خواهد. نصب پکیج OTP به‌تنهایی این تغییر ساختار را انجام نمی‌دهد.

1. همان User حفظ شود؛ حساب موازی یا ایمیل صوری ساخته نشود. شماره یکتا به حساب اصلی و ایمیل اختیاری مشتری متصل شود؛ مدیران ایمیل معتبر نگه دارند.
2. موبایل در قالب E.164 ذخیره شود؛ ارقام فارسی/عربی یکسان شوند و شماره خارجی خودکار ایرانی فرض نشود.
3. مسیر درخواست OTP با محدودیت درخواست، انقضای کوتاه، تک‌مصرف بودن و پاسخ ضد enumeration پیاده شود.
4. OTP برای purpose ورود جدا باشد تا کد ورود نتواند در بازیابی رمز/تغییر شماره مصرف شود.
5. هویت موبایل ورود از Customer.whatsapp جدا بماند؛ تغییر شماره هویتی نیازمند اثبات مجدد است.
6. ارسال واقعی از طریق آداپتر سرویس پیامک انجام شود؛ API key و pattern فقط در Secret/ENV و نه ریپو ذخیره شوند.
7. رابط فقط بعد از آزمون سرور و اتصال واقعی سرویس پیامک فعال شود.

منبع امنیتی: OWASP Authentication/MFA guidance؛ OTP باید کوتاه‌عمر، تک‌مصرف، محدود از نظر تعداد تلاش و بدون ثبت مقدار کد در لاگ باشد.
