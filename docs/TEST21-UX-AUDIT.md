# Test 21 — Subcategory Placeholder Sets UX Audit

هدف Test 21 افزودن fallback تصویری معنادار برای شش زیردسته و امکان تغییر یکپارچهٔ زبان بصری از پنل مدیریت است، بدون تغییر snapshot آزادشدهٔ Test 20.

## رتبه‌بندی الگوی پیاده‌سازی

| رتبه | الگو | مزیت | ریسک | تصمیم |
|---:|---|---|---|---|
| 1 | رجیستری نسخه‌دار + تنظیم مرکزی + پیش‌نمایش + fallback چندمرحله‌ای | یکپارچه، تست‌پذیر، قابل انتقال به backend و بدون تکرار مسیرها | در نسخهٔ production به persistence سمت سرور نیاز دارد | انتخاب و اجرا شد |
| 2 | انتخاب مستقل ست برای هر زیردسته | انعطاف حداکثری | پیچیدگی پنل و خطر ناهماهنگی بصری | فعلاً رد شد |
| 3 | تعویض با CSS class یا dataset | ساده | مدیریت خطای فایل و AVIF/WebP ضعیف | رد شد |
| 4 | ذخیرهٔ مسیر fallback روی هر محصول | کنترل جزئی | تکرار داده و مهاجرت سخت در مقیاس بالا | رد شد |
| 5 | جایگزینی هاردکدشده | سریع | فاقد کنترل مدیر و توسعه‌پذیری | رد شد |

## تصمیم‌های نهایی

- سه ست کامل `paper-cut`، `flat-geometric` و `dimensional` در رجیستری مرکزی تعریف می‌شوند.
- ست B یا `paper-cut` انتخاب پیش‌فرض است.
- هر ست برای کدهای 11، 12، 21، 22، 31 و 32 مشتق AVIF و WebP دارد.
- تصویر اختصاصی محصول همیشه اولویت دارد.
- نبود تصویر یا خطای بارگذاری به placeholder زیردسته از ست فعال ختم می‌شود.
- انتخاب‌گر مدیر از radio بومی، پیش‌نمایش، وضعیت فوکوس و متن چهارزبانه استفاده می‌کند.
- انتخاب prototype با namespace مستقل Test 21 ذخیره می‌شود؛ production بعداً آن را از تنظیمات backend دریافت می‌کند.
- Test 20 immutable می‌ماند و build جدید فقط در `/t/21` تولید می‌شود.

## سیاست رسانه

- اصل‌های تولیدشده خارج از Git نگهداری می‌شوند.
- فقط مشتق‌های بهینهٔ AVIF/WebP وارد ریپو و CI/CD می‌شوند.
- manifest مستقل، مجموعه‌ها، ابعاد، فرمت‌ها و سیاست اولویت را ثبت می‌کند.
- placeholder نباید به‌عنوان عکس واقعی یک محصول مشخص معرفی شود.
